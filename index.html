Session 1

n8n basics and your first workflow

What is automation

Automation means a computer does a repetitive task for you, the same way every time, without you clicking through it.

Without automation
A prospect fills Zenroll’s “Contact sales” form. Someone opens the responses sheet, copies the details into the team’s lead tracker, reads the requirement to check whether Zenroll can do it, decides if it’s worth chasing, and writes a reply. Twenty leads a day means twenty rounds of this, and the hot ones wait.
With automation
The form is submitted, and within a minute the lead is saved, checked, sorted, and a reply is ready. Nobody touches it until a salesperson is actually needed.

n8n is a tool for building these automations visually, by connecting boxes on a screen instead of writing code. That’s what our project does.

What is a workflow

A workflow is the full set of steps for one automation, in order. Think of it as a recipe: what starts it, and what happens after that.

Our project as a workflow: everything that should happen when a new lead comes in.

What is a node

A node is a single step in the workflow, shown as one box on the screen. Each node does one job: read the new form response, save a row, send an email, check a condition.

The workflow above has four nodes. You build a workflow by adding nodes and connecting them with lines. By Session 6, our lead workflow will have around fifteen.

Trigger

The trigger is the first node. It decides when the workflow starts. Every workflow has one starting trigger. In n8n, trigger nodes have a rounded left side.

Trigger typeWhere we use it in the project
App eventA new row appears in the form responses sheet (our main trigger)
Manual (a button)You click “Execute workflow” to test with a fake lead
ScheduleEvery weekday at 9 AM, check for hot leads nobody followed up (Session 5)
WebhookA salesperson clicks “Mark as contacted” in an email (Session 4)

Action

An action is a node that does something after the trigger. In our project: save the lead in the sheet, send an email to the sales team, update the lead’s status. Most nodes in a workflow are actions.

Trigger = when it starts. Actions = what it does.

Input

Input is the data a node receives from the node before it. The “Welcome email” node needs to know the lead’s first name and email address, so it receives them as input.

Output

Output is the data a node produces after doing its job. The Google Sheets Trigger outputs the new form response. That output goes straight into the next node.

How data flows through a workflow

Data moves from left to right. Each node’s output becomes the next node’s input.

Priya’s form response is handed from one node to the next, like a lead file passed down a line of desks.

Workflow execution

An execution is one run of the workflow, from trigger to last node. If five prospects fill the form today, the lead workflow executes five times, once per lead. n8n keeps a record of every execution so you can see exactly what happened to each lead.

Active vs inactive workflow

Inactive
The workflow only runs when you run it yourself for testing. New form responses are ignored. Like a shop with the “Closed” sign up: you can walk around inside, but no customers come in.
Active
Every new form response is picked up automatically, day or night. The “Open” sign is up.

You switch this in the top bar of the workflow. Depending on the n8n version, it’s an Active toggle or a Publish button. We keep the lead workflow inactive while building and switch it on in Session 5.

Manual execution

Manual execution means you click Execute workflow to run it right now. This is how you test while building, without waiting for a real prospect. You can also run a single node with its own play button to check just that step.

Installation (n8n Cloud or npm)

There are two ways to run n8n. For this course we use n8n Cloud, because connecting Google Forms, Sheets and Gmail takes one click there.

Option A: n8n Cloud (what we use)
Go to n8n.io and start a free trial. n8n runs in your browser. Webhooks and schedules work all the time, even when your laptop is off. Google apps connect with “Sign in with Google”. Paid after the trial ends.
Option B: on your laptop with npm (free)
Install Node.js from nodejs.org like any normal app. Check the n8n docs for the supported Node.js version first. Then run the commands below. 
# check Node.js is installed
node -v

# quickest way to start n8n
npx n8n

# or install it once, then start it any time
npm install n8n -g
n8n start

When it says it’s ready, open http://localhost:5678 in your browser. localhost just means “this computer”. To stop n8n, press Ctrl + C in the terminal.

On the laptop option, n8n only runs while the terminal is open and the laptop is awake, and connecting Google apps needs extra setup in Google Cloud Console first. That’s why the project uses Cloud.

Session 2

Data, JSON and expressions

What is JSON

JSON is the format apps use to pass data to each other. It looks like a filled-in contact card: a label, then a value. Every node in n8n sends and receives JSON. Here is Priya’s form response, exactly as the Google Sheets Trigger outputs it (switch the output panel to JSON view to see this):

{
  "row_number": 2,
  "Timestamp": "27/09/2026 10:15:32",
  "Full name": "Priya Sharma",
  "Work email": " Priya@BrightPath.in",
  "Phone": 9876543210,
  "Company name": "BrightPath Retail",
  "Company size": "51-200",
  "City": "Pune",
  "Interested in": "Demo",
  "Requirement": "Payroll and attendance for 120 staff across 3 stores. Staff should mark attendance from their phones.",
  "Timeline": "Immediately / this week"
}

Text goes in quotes. Numbers don’t. true and false are yes/no values, also without quotes. Notice the email has a stray space and capital letters. People type messy data, and we’ll clean it in this session.

Key-value pairs

Each line is a key-value pair. The key is the label ("City"), and the value is the data ("Pune"). A colon sits between them, and a comma separates each pair. In the form response, the keys are your form’s questions and the values are Priya’s answers.

Objects

An object is a group of key-value pairs inside curly braces { }. One object usually describes one thing. Priya’s whole response above is one object: one lead.

Arrays

An array is a list inside square brackets [ ]. Our three test leads, as a list:

[
  { "name": "Priya Sharma", "company_size": "51-200", "interest": "Demo" },
  { "name": "Rahul Verma", "company_size": "11-50", "interest": "Pricing" },
  { "name": "Anita Rao", "company_size": "1-10", "interest": "Support" }
]

Nested JSON

Nested means an object inside another object. In Session 6, Claude reads Priya’s lead and its answer comes back nested like this:

{
  "output": {
    "intent": "Demo request",
    "urgency": "high",
    "fit": "yes"
  }
}

To reach the fit, you go one level at a time: output, then fit, written as output.fit. Lists work the same way with a position number in square brackets, counting from 0: the first item of a list called tags is tags[0].

Items

In n8n, each object passing through is called an item. One form response = one item. If the trigger finds three new responses at once, that’s three items, and every following node automatically runs once for each item.

Three leads in, three rows saved. You don’t need to set up any repeating.

Fields

A field is one key-value pair on an item, such as city. In n8n’s Table view, fields are columns and items are rows, just like the Lead Tracker sheet.

Input data

Open the Clean lead node. The left panel shows its input: the raw form response from the trigger, with long names like “Full name” and “Work email”. You can switch each panel between Table, JSON and Schema views.

Output data

The right panel shows its output: the cleaned lead with short names like name and email. That output is exactly what “Save to Lead Tracker” receives as input.

Expressions

An expression is a value that is filled in automatically each time the workflow runs, instead of being typed once. It works like mail-merge: “New lead: name” becomes “New lead: Priya Sharma” for Priya and “New lead: Rahul Verma” for Rahul.

Dynamic values

A fixed value is the same every run: status = “New” is fixed, because every new lead starts as New. A dynamic value changes with the data: name is different for every lead. In a setting, switch from Fixed to Expression to make it dynamic.

The {{ }} syntax

Anything inside double curly braces is worked out by n8n. $json means “the data of the current item coming into this node”.

You writen8n shows (for Priya)
{{ $json.City }}Pune
{{ $json['Full name'] }}Priya Sharma
New lead from {{ $json.City }}New lead from Pune
{{ $json['Full name'] }} ({{ $json['Company name'] }})Priya Sharma (BrightPath Retail)
{{ $json.output.fit }}yes (Session 6)

Keys with spaces, like the form’s “Full name”, need square brackets and quotes: $json['Full name']. That’s one reason Clean lead renames them to simple names. The expression editor shows a live preview as you type.

Referencing previous nodes

$json only sees the node directly before. To grab data from a node further back, use its name:

{{ $('Clean lead').item.json.lead_id }}

Read it as: “from the node called Clean lead, take this item’s lead_id”. We need this later: after an email is sent, the Gmail node’s output is about the email, not the lead, so the next node reaches back to Clean lead to find which row to update. This is why clear node names matter. You can also pick earlier nodes in the input panel and drag from there.

Session 3

Workflow logic

Sequential workflows

A sequential workflow runs every step in a straight line for every item. Our workflow so far is sequential: trigger → clean → save. But Anita’s support request shouldn’t go to the sales team, and Priya’s 120-person company deserves faster attention than a 5-person one. Real work needs decisions.

A workflow follows rules that we define.

IF node

The IF node asks a yes/no question about each item and sends it down one of two paths, like a sales manager sorting lead cards into two piles. Our question: is this a hot lead?

🚦

🔀

📨

Setting it up: drag in company_size, choose String → is equal to, type 51-200. Then add conditions for 201-500 and 500+ (see 3.5). In Session 6, Claude’s urgency joins this rule.

True / false branches

The IF node has two outputs. Items that pass go out of true, the rest go out of false. Each branch can have its own nodes. Priya (51-200) goes out of true. Rahul (11-50) goes out of false.

Switch node

IF gives two paths. Switch gives as many as you need, like a receptionist sending each caller to the right department. We switch on interest:

Multiple conditions

IF, Switch and Filter can check more than one thing at once.

OR: any one is enough
company_size = “51-200” OR “201-500” OR “500+”
Our hot-lead rule. Also used in the Switch: interest = Demo OR Pricing → sales path.
AND: all must be true
status = “New” AND follow_up_date is before tomorrow
The daily reminder’s rule in Session 5.

Filter node

Filter keeps only the items that match and quietly drops the rest. Unlike IF, there is no second branch. We use it to skip test submissions, so a teammate typing “test” into the form doesn’t get emailed to a rep.

Use Filter when you don’t care about the items that fail. Use IF when both groups need something done.

Two common modes: Append stacks both lists into one (form leads + trade show leads). Combine → Matching fields joins rows that share a value, like email, similar to a VLOOKUP in Excel: for example, adding each lead’s deal stage from a CRM export.

Loop Over Items

You rarely need to build a loop, because n8n already runs each node once per item. If 20 leads come in, the email node sends 20 emails by itself. That’s why our daily reminder in Session 5 has no loop. The Loop Over Items node is for when you want control over how items are processed, most often to handle them in small groups (next topic).

Batch processing

Batching means handling items in small groups instead of all at once. Say Zenroll imports 2,000 old leads and wants to email them all. Gmail limits how fast you can send, so you’d send them in batches of 50 with a pause between: Loop Over Items (batch size 50) → Gmail → Wait → back to the loop. Our project doesn’t reach that size, so we don’t build it.

Conditional routing

Conditional routing is the general idea behind IF and Switch: sending each item down a different path based on its data. In our project the path is decided by rules we wrote in advance: interest decides the team, company size decides hot or regular.

Branches

A branch is one path coming out of an IF, Switch or any node with more than one connection. Branches run independently: the sales branch has several steps (Claude, fit check, hot check, emails), while the support branch has just two (save the route, forward the email).

Session 4

APIs, HTTP and webhooks

What is an API

An API is how one app asks another app for something. Think of a restaurant: you don’t walk into the kitchen. You tell the waiter, the waiter tells the kitchen, and the waiter brings your food back. The API is the waiter.

Every Google Sheets and Gmail node you’ve used is really an API call. n8n just hides the details. APIs exist so apps can work together safely: Google doesn’t let outsiders into its servers, but it offers a menu of things you can ask for.

Client and server

The client asks, and the server answers. When “Save to Lead Tracker” runs, n8n is the client and Google Sheets is the server. In the webhook build later, it flips: the salesperson’s browser is the client and n8n is the server.

Request

A request is the message the client sends. It says where to go (URL), what to do (method), and optionally who you are (headers) and what you’re sending (body).

Response

A response is what the server sends back: a status code saying how it went, plus the data, usually as JSON. The node’s output panel shows you this response.

HTTP

HTTP is the language requests and responses are written in. Your browser uses it every time you open a website. APIs use the same language, just returning data instead of a web page.

GET

GET means “read something”. Nothing changes on the server. When the daily reminder in Session 5 reads all rows from the Lead Tracker, that’s a GET behind the scenes. So is a salesperson clicking the “Mark as contacted” link: a browser opening any link sends a GET.

POST

POST means “create something new”. “Save to Lead Tracker” (append row) is a POST: it creates a new row. Sending an email with the Gmail node is also a POST: it creates a new message.

PUT

PUT means “replace the whole record”. If you PUT Priya’s lead, every field is replaced with what you send, and anything you leave out is wiped.

PATCH

PATCH means “change part of a record”. Changing only Priya’s status from New to Contacted is a PATCH-style change: everything else stays as it was. Most “Update row” actions work this way.

DELETE

DELETE means “remove something”. Deleting a spam submission from the Leads tab would be a DELETE. Use it carefully, because it usually can’t be undone.

URL

The URL is the address of what you’re asking for. Here’s the address of Claude’s API, which we call in this session:

https://api.anthropic.com/v1/messages

And here’s our “Mark as contacted” webhook link, which has query parameters too:

https://yourname.app.n8n.cloud/webhook/lead-status?lead_id=L-1002&status=Contacted
  • 1Base URL: which server
  • 2Path: which thing on that server
  • 3Query parameters: extra details

Query parameters

Query parameters come after the ?, in key=value pairs joined by &. In ?lead_id=L-1002&status=Contacted, the webhook learns which lead and what status. They work like filters on a shopping site.

Headers

Headers are extra details on the outside of the envelope: who’s asking, what format the data is in, and the password. Claude’s API needs three:

x-api-key: your Claude API key
anthropic-version: 2023-06-01
content-type: application/json

When the Google Sheets node calls Google, n8n adds your login as a header automatically. With the HTTP Request node, you add headers yourself.

Request body

The body is the content inside the envelope, used when you send data (POST, PUT, PATCH). When “Save to Lead Tracker” runs, the body is Priya’s cleaned lead. When we ask Claude a question, the body holds the question. GET requests usually have no body.

JSON request

The body we send to Claude’s API, asking it to read Priya’s requirement:

POST https://api.anthropic.com/v1/messages

{
  "model": "claude-sonnet-5",
  "max_tokens": 300,
  "messages": [
    { "role": "user", "content": "In one line, what does this customer need? Payroll and attendance for 120 staff across 3 stores." }
  ]
}

JSON response

Claude’s reply (shortened). The answer text sits inside content[0].text:

200 OK

{
  "role": "assistant",
  "content": [
    { "type": "text", "text": "A payroll and mobile attendance system for 120 employees at 3 retail locations." }
  ],
  "stop_reason": "end_turn",
  "usage": { "input_tokens": 31, "output_tokens": 19 }
}

In n8n, the next node reads the answer with {{ $json.content[0].text }}.

Status codes

A three-digit number that tells you how the request went. The first digit tells the story: 2 = good, 4 = you made a mistake, 5 = the server had a problem.

Some APIs reply 200 even when something is wrong and put the problem inside the data. Always look at the data, not just the code.

Authentication

Authentication is proving who you are, so Google gives your Lead Tracker only to you. Like showing your ID badge at the office door. When you clicked “Sign in with Google” for the Sheets credential, you authenticated n8n.

API key

An API key is a long secret code an app gives you, acting as a password for software. Treat it like your bank PIN: never share it in chats or screenshots.

Get your Claude API key now: sign in to the Anthropic Console (console.anthropic.com), add a small amount of credit, and create a key. Copy it once; the console won’t show it again. We use it in this session and in Session 6.

Bearer token

A bearer token is a common way of sending that secret in the headers. “Bearer” means “whoever holds this is allowed in”, like a concert ticket. After “Sign in with Google”, n8n gets a token like this and attaches it to every Sheets and Gmail request.

What is a webhook

With an API, n8n goes and asks. With a webhook, the other side comes and tells n8n. It’s a doorbell: instead of checking the door every minute, you wait for the ring.

Checking (our Sheets Trigger)
Every minute, n8n asks Google: “Any new form rows?” That’s why a lead can take up to a minute to arrive.
Webhook (they tell you)
The moment a salesperson clicks “Mark as contacted”, their browser calls n8n’s address directly. n8n reacts instantly.

Webhook URL

When you add a Webhook trigger node, n8n gives it its own address, such as https://yourname.app.n8n.cloud/webhook/lead-status. Whatever calls that address starts the workflow as an incoming request. The query parameters appear in the output under query, so {{ $json.query.lead_id }} gives L-1002.

Test URL vs production URL

Test URLProduction URL
Looks like…/webhook-test/lead-status…/webhook/lead-status

On the laptop setup, the webhook address is localhost, so only your own computer can reach it. On n8n Cloud, anyone with the link can reach it, which is what the alert emails need.

Webhook response

Whoever called the webhook waits for an answer. When a salesperson clicks the link, their browser shows whatever n8n sends back. The Webhook node’s Respond setting decides when: immediately, when the last node finishes, or through a Respond to Webhook node where you choose exactly what to send, like “Lead L-1002 marked as Contacted.”

Debugging

  1. Find the red node. That’s where it broke.
  2. Read the error. The status code tells you a lot: 401 means reconnect the credential, 404 means check the URL or sheet name.
  3. Look at its input. Was the data it needed actually there? Was a field empty or spelled differently, like “City” vs “city”?
  4. Fix and run that node alone with its own play button.

Tip: pin the trigger’s output (the pin icon in its output panel). The workflow reuses Priya’s saved data while you test, so you don’t need to submit the form again every time.

Practice
Rename the Leads tab, run the workflow, find the error in Executions, then rename it back and re-run.

Handling missing data

Form data is messy. The simplest protection happens before n8n: in the Google Form, every question is Required, and Work email uses response validation so “abc” isn’t accepted. Stopping bad data at the door is far easier than fixing it later.

Even so, always give a fallback in expressions for anything a later node depends on, in case a field arrives blank some other way (a resubmitted or edited response, for example):

{{ $json.requirement || 'No requirement given' }}

Read it as: “use the requirement, or if it’s empty, use this text instead”. Put this in Clean lead so later nodes (and Claude in Session 6) never receive a blank.

Handling API failures

Every node has a Settings tab with two useful options:

  • Retry On Fail: try again a few times, with a wait in between. Turn this on for the Gmail nodes and, in Session 6, the Claude nodes, since servers are sometimes briefly busy.
  • On Error: what to do if it still fails. Stop workflow (default) ends the run and shows it as failed in Executions. Continue skips the problem and carries on. Continue (using error output) sends failed items out of an extra error branch, where you could, for example, email yourself about it.

For this project, Retry On Fail plus the default Stop is enough: a failed lead shows up red in Executions, and you can see exactly what went wrong.

Session 6

AI, LLMs and agents in n8n

What is AI

AI is software that does tasks we used to think needed a human: understanding language, recognizing images, making judgments. Most modern AI learns patterns from huge numbers of examples instead of following hand-written rules. That learning is called machine learning.

Our workflow so far follows hand-written rules (“51-200 means hot”). It can’t read Karan’s requirement and notice Zenroll doesn’t do payroll in Dubai, or read Priya’s requirement and notice she means “this week”. AI can.

Generative AI

Generative AI creates new content: text, images, code. Writing a personal reply to Priya about her 3 stores is generative AI.

LLM

A Large Language Model is a generative AI trained on a massive amount of text. It works by predicting the most fitting next words. Claude is an LLM. So are GPT and Gemini.

Prompt

A prompt is the instruction you give the model. Better briefing, better result, just like briefing a new sales intern.

Vague
“Read this lead.”
Clear
“Read this inbound lead. Say what they want, how urgent it is (high, medium, low), whether Zenroll can meet their requirement (yes, partial, no) and why, and summarise it in one line for the sales team.”

System instructions

System instructions are the standing rules the model follows every time: its role, what it knows, and its limits. Like a job description plus a product briefing. Ours is the Zenroll product description from the project section: what Zenroll does, what it doesn’t, the list prices, and rules like “never offer discounts”.

That’s how Claude can judge fit. It has never heard of Zenroll; everything it knows about the product comes from these instructions.

User input

User input is the actual content for this run. In our workflow, it’s each lead’s details, requirement and timeline. The system instructions stay the same; the user input changes for Priya, Rahul, Karan and every lead after.

Model response

The model’s answer. In n8n it arrives as JSON output like any other node, ready to be mapped into an email or a sheet column.

Tokens

Models read and write text in small pieces called tokens, roughly ¾ of a word in English. Pricing and limits are counted in tokens. Reading one lead and drafting a reply is a few hundred tokens, a tiny cost per lead.

Context

Context is everything the model can see when answering: the system instructions, the conversation so far, and any data you pass in. Claude only knows about Priya because we put her details in the prompt. It can’t see the Lead Tracker unless we give it the data or a tool.

Temperature / model settings

Temperature controls how creative versus predictable the answers are. Low (near 0) gives consistent answers, which suits sorting leads into urgency levels. Higher gives more variety, which suits brainstorming email subject lines. Other settings include which model to use and the maximum length of the answer.

Hallucination

Sometimes a model states something false with full confidence, like inventing a price or a feature in a reply to Rahul. It’s predicting plausible words, not checking facts. Reduce it by giving real data in the context, telling it what not to do (“never promise prices”), and checking important outputs before they go to customers.

Structured output

Instead of free text, ask the model to answer in a fixed JSON shape. Then n8n can use each field in later nodes: an IF on fit, an IF on urgency, a sheet column for summary.

Workflow vs Agent

Workflow
Same steps every time, in the order you set. Predictable and cheap. Right for the lead pipeline, because every lead should be saved, routed and checked the same way.
Agent
The model reads the situation and decides what to do and when to use its tools. Flexible. Right for writing a reply, because every hot lead needs a different message.

Our project uses both: a workflow for the process, with an agent inside it for the one step that needs judgment.

A workflow follows rules we define. An agent decides which action or tool to use based on the situation.
